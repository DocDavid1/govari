# גוב ארי — שרת הזמנות אונליין

תשתית מלאה להזמנות מהאתר: קליטת הזמנה, שמירתה, שליחת **אישור ללקוח** ו**התראה על כל הזמנה למייל שלך**, ונקודת חיבור אחת לספק הסליקה. כשמחברים סליקה — האתר הופך לחנות מלאה.

## מה כבר עובד (גם בלי סליקה)
- עמוד צ'קאאוט (`site/checkout.html`) → שולח הזמנה לשרת.
- ההזמנה נשמרת ב-`data/orders.json`.
- **מייל התראה אליך** (`OWNER_EMAIL`) על כל הזמנה חדשה.
- **מייל אישור ללקוח**.
- עמוד תודה (`site/order-success.html`).
- "מצב לידים": עד שמחברים סליקה, הזמנה = ליד (נשמר + מייל). אחרי חיבור סליקה = תשלום מלא.

## התקנה והרצה (מקומית)
דרוש Node.js גרסה 18 ומעלה.
```bash
cd server
npm install
cp .env.example .env      # ואז ערוך את .env
npm start
```
פתח בדפדפן: http://localhost:3000 — האתר כולו מוגש מהשרת (כולל הצ'קאאוט).

| `OWNER_EMAIL` | לאן מגיעה התראה על כל הזמנה (כבר: davidazulay75@gmail.com) |
| `RESEND_API_KEY` | מפתח מ-resend.com לשליחת מיילים |

## הפעלת המיילים (Resend)
1. הירשם ב-https://resend.com (יש תוכנית חינם).
2. אמת דומיין (Domains → Add Domain) — נדרש כדי לשלוח מ-`orders@govari.co.il`.
   לבדיקות מהירות אפשר להשתמש ב-`onboarding@resend.dev` כ-`FROM_EMAIL`.
3. צור API Key והדבק ל-`RESEND_API_KEY`.
בלי מפתח — השרת רץ, מדלג על מיילים ורושם אזהרה (נוח לפיתוח).

## בדיקת התהליך המלא — ללא תשלום (קופון FREE)
כדי לבדוק הזמנה + מיילים מקצה לקצה בלי סליקה ובלי חיוב:
1. הפעל את השרת: `npm start`.
2. גלוש דרך כתובת השרת — **http://localhost:3000/checkout.html** (לא לפתוח את הקובץ ישירות! פתיחה כקובץ נותנת שגיאת "Failed to fetch" כי אין שרת מאחורי הדף).
3. מלא פרטים, בשדה **קוד קופון** הזן `FREE` ולחץ "החל" — הסכום יורד ל-0.
4. לחץ "המשך" → ההזמנה נוצרת, מסומנת כ"שולם", ונשלחים: מייל אישור ללקוח + התראה אליך. הגעת לעמוד תודה.

> להוספת/שינוי קופונים: ערוך את `src/coupons.js` (למשל `LAUNCH10: { percent: 10 }`).
> קופון FREE נועד לבדיקות — מומלץ להסירו לפני עלייה לאוויר.

## חיבור ספק הסליקה (השלב האחרון)
כל הלוגיקה מרוכזת בקובץ אחד: **`src/payment.js`**. יש שם שתי פונקציות למלא:
1. `createCheckout(order, {returnUrl, webhookUrl})` — קורא ל-API של הספק ומחזיר כתובת דף התשלום.
2. `verifyWebhook(req)` — מאמת את ההודעה מהספק ומחזיר `{orderId, paid, ref}`.

בקובץ יש דוגמה כללית והערות מדויקות לפי ספק (PayPlus, משולם/Grow, Cardcom, Tranzila, Stripe).
אחרי המילוי, הגדר ב-`.env`:
```
PAYMENT_PROVIDER=payplus        # או grow / cardcom / tranzila / stripe
PAYMENT_API_URL=...
PAYMENT_API_KEY=...
PAYMENT_WEBHOOK_SECRET=...
```
זהו — האתר סולק תשלומים. הזרימה: צ'קאאוט → דף תשלום של הספק → webhook מאשר → מייל אישור ללקוח + התראת "שולם" אליך.

## זרימת המערכת
```
לקוח ממלא checkout.html
        │  POST /api/orders
        ▼
  יצירת הזמנה + שמירה  ──►  מייל התראה אליך (תמיד)
        │
        ├─ יש סליקה?  כן ─►  הפניה לדף התשלום ─►  webhook ─►  מסומן "שולם"
        │                                               └─►  מייל אישור ללקוח + "שולם" אליך
        └─ אין סליקה ─►  מייל "קיבלנו הזמנה" ללקוח ─►  עמוד תודה
```

## העלאה לאוויר (פרודקשן)
מומלץ Render (יש תוכנית חינם) או Railway:
1. העלה את התיקייה לגיטהאב.
2. ב-Render: New → Web Service → בחר את הריפו. Root Directory: `server`. Build: `npm install`. Start: `npm start`.
3. הגדר Environment Variables (כל מה שב-.env).
4. עדכן `SITE_URL` לכתובת שקיבלת, וכוון את הדומיין שלך.
השרת מגיש גם את האתר וגם את ה-API מאותה כתובת — פריסה אחת לכל.

## נתיבי API
- `POST /api/orders` — יצירת הזמנה
- `POST /api/payment/webhook` — אישור תשלום מהספק
- `GET  /api/payment/return` — חזרת הדפדפן מהסליקה → עמוד תודה
- `GET  /api/orders/:id` — סטטוס הזמנה
- `GET  /health` — בדיקת חיים

## אבטחה
- אין שמירת פרטי אשראי אצלנו — התשלום מתבצע בדף המאובטח של הספק (PCI).

- ודא HTTPS בפרודקשן (Render מספק אוטומטית).
